# Standalone player experiment

Sawbyte's main runtime is independently written Rust. The optional Java/Fabric bridge exists to exercise the normal client with matching inputs. It is not required by the native runtime and is not the main product.

This milestone targets Minecraft Java **26.3 only**. It is a controlled movement experiment, not a general-purpose playable client or a launcher release.

## What the workflow checks

`Real player milestone` builds and tests the native executable on Linux x86-64, Windows x86-64 and macOS ARM64. Its Linux comparison job then:

1. Downloads the official server and generates version-specific block IDs from its data report.
2. Starts an ephemeral loopback-only, offline flat-world server.
3. Runs the native player through a 160-tick recording: wait, walk, turn, jump and stop.
4. Runs the same recording in a normal Fabric client using a virtual display.
5. Checks movement, complete traces and position differences (maximum 0.001 blocks), plus ground-state agreement.

The `player-comparison-evidence` artifact contains logs, CSV traces, block IDs and measurements. A failed job is evidence of unfinished work. Passing this scenario establishes only that scenario; it does not establish complete client equivalence, online authentication or Windows/macOS gameplay parity.

The native process's sampled peak RSS is recorded separately. Server and graphical-client processes are not included in that number. It is not a comparison against other automation clients, and no production memory target is established.

## Experimental command line

All compilation and lab execution happen in GitHub Actions. Download the player artifact for your platform and use `sawbyte-play --help` to inspect its commands. There is no graphical launcher yet.

```text
sawbyte tape movement.sbif
sawbyte-play 127.0.0.1:25565 --offline SawbyteNative movement.sbif native.csv block-profile.json
sawbyte-play login <registered-microsoft-client-id> <new-token-file>
sawbyte-play 127.0.0.1:25565 --account <token-file> movement.sbif native.csv block-profile.json
```

The tape generator is the separate foundation `sawbyte` executable. The block profile must come from the matching version's official data report, as generated by the CI lab. It is currently restricted to air and ordinary full cubes. Do not treat this profile or executable as a supported arbitrary-server client.

Online login requires an application registration permitted to use the relevant Microsoft/Xbox/Minecraft services and an eligible Minecraft account. That flow has not been validated with a live account. It stores a short-lived access token, does not refresh it, and must not be committed or shared. Unix token files are created with owner-only permissions; Windows credential-store integration is unfinished.

## Deliberate limitations

- Motion currently covers ordinary-ground walking, turning and a single jump, with full-cube collision. Other terrain, fluid movement, effects, attributes, vehicles, sprinting, sneaking, flying and complete entity interactions are unfinished.
- Loaded chunks are bounded to 256. Unknown collision states, unavailable collision data, loaded-world block updates, death and session transitions stop the prototype.
- Inventory, clicks, combat, chat, text fields, dialogs and custom GUI automation are not exposed yet. The complete player-action requirement remains the product goal.
- Some unimplemented server packets are ignored; this is one reason the experiment is restricted to the controlled lab. It cannot guarantee correct behaviour on arbitrary servers.
- The bridge stops on screens opening during replay, death or disconnect. Its CSV `chunks` field records whether the current chunk is loaded (0 or 1), whereas the native trace records its cached chunk count.
- The supplied Sawbyte icon is included in artifacts and the README. A branded launcher, embedded platform icons and installers remain separate packaging work.

Before a usable client preview: pass the controlled comparison, add coverage for collision and input edge cases, handle changing world state and player attributes, validate online sessions, and provide a supported installation/account/profile workflow. Full automation and multi-version support require further milestones.
